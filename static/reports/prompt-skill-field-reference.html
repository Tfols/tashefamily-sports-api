L1

Prompt Layer

The system instructions, tool schemas, in‑context examples, and output rules an agent reasons from on every turn — the substrate everything else is built on.

Proven levers

  • Chain‑of‑thought: induce step‑by‑step reasoning before an answer
  • Few‑shot examples: show, don't just tell, the desired output
  • Structured tool schemas: unambiguous names, explicit parameters
  • Explicit output‑format constraints
⚠ CENTRAL FINDING — PROMPTS ARE BRITTLE

Purely cosmetic formatting changes (delimiters, spacing) have swung task performance by up to 76 points with content held constant. Few‑shot example order shifts accuracy and the best order rarely transfers between models.

Sclar et al. 2024 · Lu et al. 2022 · Zhao et al. 2021

Working defense

  • Test multiple phrasings / formats — never trust one hand‑tuned draft
  • Write tool specs like onboarding docs for a new hire: explicit context, example calls, no ambiguity
  • Fix tool clarity before splitting into more agents

RISK — INDIRECT PROMPT INJECTIONMalicious instructions hidden in tool output (a page, a doc, an email) can hijack an agent. Best current defenses (delimiters, repeating instructions, tool‑set restriction) still cost ~15–20% task utility when actively attacked. AgentDojo, NeurIPS 2024

L2

Skill Layer

A folder — SKILL.md plus optional scripts, references, assets — packaging reusable procedure so it doesn't need re‑explaining every session. Now an open, cross‑platform standard, not one vendor's feature.

Mechanism: progressive disclosure

  • Tier 1 — name + description only (always loaded, ~cheap)
  • Tier 2 — full SKILL.md body (loaded once triggered)
  • Tier 3 — reference files / scripts (loaded only if needed)
⚠ CENTRAL FINDING — AVAILABILITY ≠ USE

Having a skill installed does not guarantee it's used effectively. Benefit depends heavily on the model and agent framework, and many popular community skills don't reliably beat the base agent — especially on reasoning‑heavy (not procedural) tasks.

OpenSkillEval, 2026 · 600+ tasks, 30 skills

Working defense

  • The description field carries the entire triggering burden — test it against prompts that should / shouldn't fire it
  • Numbered steps + concrete templates beat prose explanation
  • Keep the main file lean; push edge cases to reference files

RISK — SKILL.MD IS ATTACK SURFACEMetadata text itself can be gamed to bias which skill an agent selects or how it ranks in a registry. Open community registries have had real incidents — one campaign planted hundreds of typosquatted, credential‑stealing skills before it was caught. Under the Hood of SKILL.md, 2026 · "ClawHavoc" incident

The one rule that governs both layers: measure, don't assume

A prompt or a skill can read as perfectly clear and still fail unpredictably. The only defense the evidence supports is empirical: build a small evaluation set (20–50 real cases is enough to start), test variants against it, and revise based on observed failures — not on how confident the instructions sound.
